# CONTEXT.md: AGOS-Offline Domain Model

## System Overview

**AGOS-Offline** is an on-premises, edge-resilient local computer vision system for Philippine Local Government Unit (LGU) Disaster Risk Reduction and Management Offices (DRRMO).

It ingests RTSP video streams from municipal CCTV cameras overlooking drainage grates and canal culverts, detects solid waste obstructions using an on-device YOLOv8 ONNX binary debris model, measures grate occlusion percentage over a calibrated Region of Interest (ROI), and alerts operators via audible sirens, two-way VHF/UHF radio dispatch tickets, and local Android SMS gateway broadcasts.

---

## Ubiquitous Language & Glossary

### Ingestion & Visual Layer
- **CCTV Stream:** IP camera video feed delivered over local RTSP (`rtsp://`), local MP4 test loop, or USB webcam on the command center network.
- **Drainage Grate:** The physical metal bar grill or concrete culvert inlet at road curb level where runoff enters the underground drainage system.
- **Region of Interest (ROI):** A normalized rectangular bounding box `[x_min, y_min, x_max, y_max]` that can be calibrated on the camera view to designate the active drainage grate intake opening. The default ROI is the full frame `[0.0, 0.0, 1.0, 1.0]`.
- **Binary Debris Detection:** Solid waste detection is strictly binary with a single target class: `debris`. All trash items (plastic bags, bottles, sacks, tires, styrofoam, vegetative clusters) are detected under this single class. Multi-class classification is not used; detection focuses purely on bounding-box localization to compute physical width occlusion across the drainage grate intake.

### Occlusion & Metrics
- **Occlusion Ratio (width coverage):** The percentage ($0.0\%$ to $100.0\%$) of the ROI width covered by detected debris: the merged horizontal span of the debris boxes, clipped to the ROI x-range, divided by the ROI width. Only boxes overlapping the ROI vertically count, and box height is otherwise ignored.
- **Clear Status:** Occlusion ratio $< 20\%$. Normal runoff flow, no intervention needed.
- **Warning Status (Maintenance/Inflow Alert):** Occlusion ratio between $20\%$ and $59\%$. Indicates accumulating trash and reduced intake capacity; opens an incident record in SQLite to queue preventive maintenance dispatch.
- **Critical Blocked Status:** Occlusion ratio $\ge 60\%$. Urgent obstruction presenting immediate flood back-up risk; opens an incident record or upgrades an existing WARNING incident record in place to CRITICAL.
- **Temporal Hysteresis / Smoothing:** A rolling 2-of-3 frame filter window requiring multiple consecutive flagged frames to prevent transient floating objects from triggering false alarms.

### Emergency & Dispatch Layer
- **Command Center Console:** The local web dashboard running on `localhost:5173` or `localhost:8000` accessible to DRRMO desk operators.
- **Audible Siren:** Web Audio API sound alarm generated by the console upon sustained Critical Blocked status.
- **Radio Dispatch Ticket:** A structured verbal call script formatted for LGU two-way VHF/UHF radio operators to immediately dispatch barangay tanods or mobile declogging crews.
- **Android SMS Alert Gateway:** An on-premises Android phone SMS gateway (`SMSGate` / local cellular SIM gateway) communicating over local HTTP without external cloud SMS API dependencies. Operators and automated critical alert triggers broadcast instant text messages directly over cellular carrier networks to field responders and barangay personnel even during wide-area ISP and fiber backhaul failures. Supports live and mock operating modes, ping health checks, delivery cooldown throttling, and retry policies.
- **Responder Teams & Groups:** Local operational directories of field response personnel (e.g., Barangay Tanods, Quick Response Teams, City Engineering Declogging Crews) organized into responder groups. Each responder profile includes mobile contact numbers, active deployment status, assigned zones, and granular notification preferences.
- **Dual-Channel Dispatch:** DRRMO operators can alert field responders via **both local two-way radio tickets and Android SMS gateway broadcasts**, providing full communication redundancy (voice radio callouts + text broadcast) during severe disaster conditions.
- **Incident Lifecycle (Warning & Critical):** Both WARNING (maintenance/inflow alert) and CRITICAL obstructions open incident records in SQLite (`agos.db`). Exactly one open incident is tracked per camera at a time (`is_open = 1`). If an obstruction begins at WARNING and accumulation worsens to $\ge 60\%$, the existing WARNING incident is **upgraded in place to CRITICAL** (retaining the record ID, updating status to CRITICAL, updating duration, and rewriting the stored frame snapshot if coverage establishes a new peak). An incident record only escalates (WARNING $\rightarrow$ CRITICAL, never downgraded while open). When the obstruction clears and confirmed status returns to CLEAR, the open incident is closed (`is_open = 0`, recording closed timestamp and final duration). Automated SMS alerts are dispatched on CRITICAL status and incident resolution.
- **Offline Incident Log:** An incident record persisted in embedded SQLite (`agos.db`) with timestamp, occlusion percentage, camera identifier, and annotated JPEG frame stored on local disk (`storage/incidents/`).
- **Store-and-Forward Queue:** An outbound synchronization queue in SQLite that holds offline events and syncs to Supabase cloud whenever internet connectivity is restored.

### Cadence, Weather & Model
- **Inference Cadence (Clear / Burst / Settled):** How often the model runs. Clear scans every 15 s, Burst every 3 s once debris appears, and Settled every 10 s while a confirmed Critical blockage persists.
- **Open Incident:** The single in-progress blockage record for a camera, opened on confirmed WARNING or CRITICAL. Its occlusion, severity level (upgraded in place from WARNING to CRITICAL upon escalation), and duration update until a confirmed Clear status closes it.
- **Rain Hazard:** An operator-facing flag set when rainfall reaches the PAGASA orange warning level (15 mm/h by default) or an operator override. It informs dispatch decisions and never changes alarms, cadence or incident creation.
- **Model & Dataset Provenance:** The deployed YOLOv8 ONNX model (`backend/app/ml/weights/best.onnx`) was trained using the **TACO dataset + previously captured real-world debris images** (not from the original AGOS dashboard deployment). Debris detection is binary (`debris`) with zero multi-class classification.
- **Model Sidecar:** The `best.onnx.json` file next to the weights holding version, training source (`"TACO dataset + previously captured real-world debris images"`), SHA-256 and licence. A mismatch with the actual file is shown as `sidecar_hash_match: false`.
