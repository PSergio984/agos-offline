# AGOS-Offline: debris detector training pipeline

Isolated toolchain to assemble a licence-checked public dataset, fine-tune YOLOv8n, gate the ONNX export on measured recall, and deploy to the offline console. Nothing here is imported by the runtime; heavy PyTorch/Ultralytics dependencies stay in `venv-train`.

## Honest status

- **Validated on public data only.** No LGU/CCTV footage was collected or hand-labelled. Public photos (close-range street and beach litter) are a different domain from a drain-grate camera, so these numbers are indicative, not a field accuracy claim.
- **Licence of the model.** The weights derive from Ultralytics YOLOv8 and `ultralytics` itself is **AGPL-3.0**. The trained model is therefore AGPL-3.0 as well. Do not describe it as "open" in a permissive sense or as MIT. If you distribute or network-serve it, AGPL-3.0 obligations apply.
- **Dataset licences.** Only allowlisted licences are ingested: CC0-1.0, CC-BY-2.0/3.0/4.0, MIT, Apache-2.0, public domain. NC, ND, SA, GPL-family, custom and unknown licences are excluded, and a source with no recorded licence is a hard error. See `ml_pipeline/DATASET_LICENSES.md` (generated by `prepare_dataset.py`).
- **Privacy.** Faces and plates are blurred with OpenCV Haar cascades. Plate recall, especially for Philippine plates, is only partial. Only public images are processed.

## Measured baseline of the shipped weights (before any retraining)

Measured with `ml_pipeline/baseline_eval.py` on 300 TACO photos (local checkout, per-image licences unverified, baseline only) and 60 licence-filtered Wikimedia Commons negatives, through the production `YOLOInference` at conf 0.35 / NMS IoU 0.50:

| Metric | Value |
| :--- | :--- |
| Box recall @IoU 0.5 | 0.0376 (33 of 877 boxes) |
| Box precision | 0.0437 |
| Image recall | 0.5700 |
| Negative FP rate | 0.6667 (40 of 60) |

The negatives are not hand-verified litter-free, so some false positives may be real litter.

CPU benchmark of the same ONNX (`export_and_benchmark.py`, ONNX Runtime CPUExecutionProvider, 4 intra-op threads, 50 runs, one real image, the development machine used for this work): 27.9 ms mean, 33.7 ms p95, 35.8 FPS, 11.70 MB. Other machines will differ.

## Runtime cadence (for context)

Frames are acquired continuously; inference runs on a schedule: 15 s while CLEAR, 3 s in burst, 10 s once a blockage has stayed CRITICAL (settled). Burst starts when the raw occlusion reaches 2.0% of the ROI or the confirmed status leaves CLEAR, and ends only after 3 clean inferences, a 15 s minimum dwell and a 60 s cooldown. Rain data never changes the cadence.

The `cu126` tag is an example; pick the current one for your driver.

## 1. Build the dataset

```powershell
python ml_pipeline\prepare_dataset.py            # default output: ml_pipeline\dataset_public (git-ignored)
```

Collapses every source to class `0: debris`, adds roughly 12% clean negatives with empty labels, splits by group, blurs faces and plates, and writes `data.yaml`, `manifest.json` and `DATASET_LICENSES.md`. `--generate-starter` writes a synthetic smoke-test set (`"synthetic": true`) that `train.py` and the export gate refuse. Roboflow sources are only used when `ROBOFLOW_API_KEY` is set.

## 2. Train

```powershell
python ml_pipeline\train.py --device 0 --hours 1.0 --epochs 50 --batch 16
```

Output: `ml_pipeline\runs\debris_yolov8n\weights\best.pt` (git-ignored).

## 3. Gate, benchmark and deploy

```powershell
python ml_pipeline\export_and_benchmark.py --weights ml_pipeline\runs\debris_yolov8n\weights\best.pt --deploy
```

The script exports ONNX (opset 12, 640), checks the contract (`[1,3,640,640]` to `[1,5,8400]`, class `debris`), evaluates the validation split with the production inference code, benchmarks CPU latency, and writes `ml_pipeline\runs\gate\gate_report.{json,md}`.

- Gate: box recall >= 0.80, negative FP rate <= 0.10, and at least 20 negative validation images.
- Gate failed: exit code 2, `backend\app\ml\weights\best.onnx` is never touched.
- Gate passed and `--deploy` given: current weights are copied to `best.previous.<sha8>.onnx` (git-ignored), the new weights are copied in, and `best.onnx.json` is rewritten with version, SHA-256, training source, metrics and licence.
- Without `--deploy` nothing is ever replaced.

Refusal check run on this machine against the shipped weights with `--min-recall 0.999 --deploy` on the baseline public data: gate FAIL (recall 0.0376, negative FP rate 0.6667), exit code 2, SHA-256 of `best.onnx` unchanged.

After a deploy, restart the backend and re-run `python sample_media\verify_real_demo.py`.
